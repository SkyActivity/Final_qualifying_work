## 3.1 Тестирование

Тестирование приложения и модели проводится поэтапно, чтобы подтвердить
работоспособность системы, корректность обработки данных и устойчивость к
ошибкам. Выделены четыре ключевых вида тестирования.

1. Смоук-тестирование — проверка запуска и базовых функций.
2. Позитивное тестирование — работа только с корректными данными.
3. Негативное тестирование — проверка некорректных данных и операций.
4. Тестирование критического пути — проверка основного пользовательского сценария.

### Пример кода (Django TestCase)

```python
from django.test import TestCase
from django.urls import reverse


class SmokeTest(TestCase):
    def test_home_page_loads(self):
        response = self.client.get(reverse("dashboard"))
        self.assertEqual(response.status_code, 200)
        self.assertIn("VisualData", response.content.decode("utf-8"))
```

### Таблица 3.1 — Примеры тест-кейсов

| Тест-кейс | Вход | Ожидаемый результат |
|---|---|---|
| Запуск приложения (смоук) | Запуск сборки | Приложение стартует без ошибок, отображается главная страница |
| Доступ к базовой функции (смоук) | Нажатие на кнопку "Загрузить данные" | Открывается форма загрузки, нет ошибок |
| Корректная загрузка данных (позитив) | Файл в допустимом формате (например, CSV) | Данные загружаются, отображается подтверждение |
| Корректный запуск модели (позитив) | Валидные данные и параметры | Модель выполняется, выдает результат |
| Некорректный формат данных (негатив) | Файл с неверной структурой | Выводится сообщение об ошибке, приложение не падает |
| Пустой ввод (негатив) | Пустая форма/пустой файл | Выводится предупреждение, операция не выполняется |
| Выход за допустимые диапазоны (негатив) | Значения вне диапазона | Показано сообщение о некорректном вводе |
| Критический путь пользователя | Вход → загрузка данных → запуск модели → просмотр результата | Сценарий выполняется без ошибок, результат корректно отображается |
